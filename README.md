# Eventer

Append-only store for JSON events. A typed schema fixes the columns. Rows are packed into columnar blocks, compressed with zstd, and written to segment files. A sparse index records each block's minimum and maximum timestamp so a time-range read can skip blocks that cannot match. A zone map next to that index records equality stats for the other columns, so a filtered read can skip a block whose payload cannot contain the value. The timestamp column is the sparse-index range, so a new zone file stores that column as a one-byte tag.

The library is both an rlib and a cdylib (`libeventer.so` / `eventer.dll`) with a small C API. `eventer-server` links the rlib and serves the HTTP routes.

## Schema

Events are JSON objects. The schema names the timestamp field and the column types. Field order is the on-disk column order. Unknown JSON fields are ignored. Missing values become null, except the timestamp, which is required.

Types: `int` (i64), `float` (f64), `bool`, `string` (dictionary-encoded when that is smaller), `text` (dictionary-encoded when that is smaller), `decimal` (JSON string, stored as i128 with a schema scale), `timestamp` (unix milliseconds, or an RFC3339 string such as `2024-01-02T03:04:05.123Z`), `json` (any JSON value other than null). A `json` column returns the nested value as JSON, so one field can hold an object on one row, an array on the next, and a scalar after that. The stored form keeps the original field text from ingest (including key order, whitespace inside the value, and duplicate object keys). Dictionary encoding is used only when repeated values in a block make it smaller. JSON null and a missing field are both column nulls; a repeated top-level field follows last-wins semantics like `serde_json`.

```json
{
  "timestamp_field": "ts",
  "fields": [
    {"name": "ts", "type": "timestamp"},
    {"name": "user_id", "type": "int"},
    {"name": "score", "type": "float"},
    {"name": "ok", "type": "bool"},
    {"name": "action", "type": "string"},
    {"name": "note", "type": "text"},
    {"name": "amount", "type": "decimal", "scale": 2},
    {"name": "props", "type": "json"}
  ]
}
```

The first open writes `schema.lock` into the data directory. A later open may append fields at the end of that locked list. The lock file is rewritten to the new canonical schema, and rows stored before the append read null for the new columns. Old segment files stay as they were written. A different timestamp field, a type or decimal-scale change, a removed field, a renamed field, or a reordered field is rejected.

## Run the server

```bash
mkdir -p data
cargo run -p eventer-server -- --data ./data --schema examples/schema.json --bind 127.0.0.1:43123
```

`POST /events` takes one JSON object, or a JSON array of objects, and returns after that write is fsynced. An object responds with `{"ok":true}`. An array is validated in full before any row is queued, then stored with one fsync, and responds with `{"ok":true,"count":N}`. An empty array, or an array containing a value that is not an object or does not match the schema, is rejected and leaves the store unchanged.

```bash
curl -sS -X POST http://127.0.0.1:43123/events \
  -H 'content-type: application/json' \
  --data '{"ts":1700000000000,"user_id":7,"score":1.5,"ok":true,"action":"click","note":"demo","amount":"19.99","props":{"plan":"pro","flags":["a",1]}}'
```

`GET /events?from=&to=` returns a JSON array. `from` and `to` are inclusive unix milliseconds. Repeat `eq=field=value` to keep rows where that column equals the value. Repeat `gt`, `ge`, `lt`, and `le` as `field=value` to keep rows on one side of a numeric threshold. `gt` and `lt` are exclusive. `ge` and `le` are inclusive. An int bound is a base-10 integer in the `i64` range. A decimal bound uses the same text as `eq` for that column. A float bound is a finite number. A bool, string, text, or json column, a missing field, a missing value, or a value the column cannot parse is status `400` and does not read the store. Nulls do not match a range. Every filter is AND-ed. Blocks the zone map can reject are not read; an integer, decimal, or float zone whose maximum is below a lower bound, or whose minimum is above an upper bound, is one of those, including the exclusive cases. A float equality still reads a block whose range contains the value. JSON is not a skip. The rest are filtered while they are decoded. `limit` is a positive integer: the response is the first that many matching rows, in ingest order. `offset` is a non-negative integer and skips that many matching rows before `limit` is applied. `offset` without `limit` returns the rest, and an offset past the last match returns `[]`. Omitting both returns every match. `limit=0`, a negative limit, a negative offset, or a non-integer is status `400`.

Repeat `select=field` to keep only those fields. The objects contain the selected fields in schema order, and naming a field twice selects it once. A selected null is JSON `null`. A field that was not selected is absent. Selecting every column matches the keys of the response without `select`. An empty name, an unknown field, or a parameter other than `from`, `to`, `limit`, `offset`, `eq`, `gt`, `ge`, `lt`, `le`, and `select` is status `400` and does not read the store. Filters still apply, including a filter on a column that is not selected. A block the sparse index or the zone map can reject is not read. A column that is neither selected nor needed by a filter is not decompressed. An older single-frame block still decodes, and the omitted values are dropped after decode. `select` on `GET /events/count`, `GET /events/histogram`, `GET /events/stats`, and `POST /events/drop` is status `400`.

`GET /events/count?from=&to=` returns `{"count":N}` for that same range and the same `eq` and range filters. `N` is the number of rows the unpaged `GET /events` response would contain. `limit` and `offset` are rejected. A block the zone map can reject is not read. A block with no predicates counts payload timestamps and does not decode the other columns. Columns after the last predicate are not decompressed. When an int, decimal, or float zone already sits inside every range on that block and the column has no nulls, count uses that same timestamp path and does not decode the proved column. A null in the zone, a bound the zone does not cover, or an equality on a numeric or json column still decodes. One equality on a string or text column, with no other predicate, counts a constant string or one period of dictionary codes from the column header when every payload timestamp is inside the inclusive range. A null, a full per-row code vector, raw strings, a second predicate, or a timestamp outside the range still walks rows. The sparse index is not that check. A constant or a positive non-wrapping timestamp stride may prove it; any other timestamp encoding still expands. One equality on a bool column, with no other predicate, counts a constant bool or one bitmap period from the column header when every payload timestamp is inside the inclusive range. The period is repeated, and a bool is not expanded per row. A null, a full per-row bitmap, a second predicate, or a timestamp outside the range still walks rows. When that count also has numeric ranges and the zone implies every one of them, those ranges are dropped before the header count and the range columns stay compressed. A null in the zone is not a proof. A bound the zone does not cover still walks. The sparse index is not that check. A constant or a positive non-wrapping timestamp stride may prove it; any other timestamp encoding still expands. Histogram bucket totals still match count.

`GET /events/stats?from=&to=` returns `{"columns":{"<field>":{...}}}` for that same range and the same `eq`, `gt`, `ge`, `lt`, and `le` filters. Repeat `sum=field`, `min=field`, `max=field`, `var=field`, and `stddev=field`. At least one is required, and the same field may be named by more than one of them. Each column object contains only the stats that were requested. `min` and `max` use the same JSON form as that column in `GET /events`. `sum` of an int, a decimal, or a timestamp is a JSON string of the exact total. `sum` of a float is a JSON number. Nulls do not contribute. When every matching value is null, or the filter matches no rows, `min` and `max` are JSON `null` and `sum` is `"0"` for an int, decimal, or timestamp, or `0` for a float. An int, decimal, or timestamp sum that does not fit in 128 bits is status `400` and returns no partial object. A float sum is IEEE-754 addition in ingest order. `var` is the population variance and `stddev` is its square root. Nulls do not contribute. No non-null match, including a filter that matches nothing, is JSON `null` for both, not zero. One non-null value is `0`. A float `var` and `stddev` are JSON numbers. The variance is the IEEE-754 value of `(sum_of_squares / n) - (sum / n)^2`, including a finite negative result of cancellation. Both sums accumulate in ingest order inside a block and in block order across the store, the same order a float sum uses. `var` returns that number. `stddev` is the square root of a non-negative variance. A finite negative variance together with `stddev` is status `400`, the message is `variance of \`<field>\` is negative; the computed variance is negative`, and the body is not a column object. An int or timestamp `var` is a JSON string of the exact rational `(n * sum_of_squares - sum^2) / n^2` in lowest terms, in the same integer units the 128-bit sum accumulates. A decimal `var` divides that rational by `10^(2*scale)` and reduces again, so it uses the same decimal units as `sum`. Scale 2 stores `1.00` and `2.00` as `100` and `200`; the variance is `"0.25"` and the standard deviation is `0.5`, next to `sum` `"3.00"`. `1.00`, `2.00`, and `3.00` are `2/3`. Scale 0 is unchanged. A denominator of 1 is the integer digits with no slash. A denominator whose prime factors are only 2 and 5 is the shortest decimal. Anything else is `numerator/denominator` with a positive denominator. `stddev` of those types is a JSON number, the f64 square root of that rational. A non-finite float is the same corrupt error a float sum returns, and the body is not a partial column object. A variance that does not fit in that 128-bit accumulator is status `400` and not a partial object. One float sum, with no minimum, no maximum, no variance, and no row predicate, adds a block from that column's encoded values when every payload timestamp is inside the range and the column has no nulls. A null, a non-finite value, or a block the range cuts still visits the matching rows. The sparse index is not that inside check. `limit`, `offset`, `select`, `quantile`, `distinct`, `topk`, and `bucket_ms` are rejected. A missing list, an empty field name, an unknown field, or a bool, string, text, or json column is status `400` and does not read the store. A block the sparse index places outside the range is not read. A block the zone map can reject is not read. `min` and `max` are the min and max of the rows that survive the filters. When the request is only `min` and `max`, with no `sum`, no `var`, no `stddev`, and no row predicate, a block whose payload timestamps are all inside the range answers int, decimal, and float extremes from the zone map, including a column that also contains nulls. An all-null column is a null minimum and a null maximum. An unknown zone, including a non-finite float, still decodes that column. A block with any timestamp outside the range decodes the stat columns and keeps the in-range rows. The sparse index is not that check. A `sum`, a `var`, a `stddev`, a grouped aggregate, or a predicate still decodes. `by=field` returns `{"groups":[{"key":...,"columns":{...}}]}` instead, one group per value of that single column. A second `by`, an empty name, an unknown field, a float, or a json column is status `400` and does not read the store. `by` may name a column that is also a `sum`, `min`, `max`, `var`, or `stddev` target. `key` uses the same JSON form as that column in `GET /events`, and a null key is JSON `null`. Groups are ordered by the key: null first, then numeric order for int, timestamp, and decimal, `false` then `true` for bool, and byte order for string and text. More than 4096 groups is status `400` and the body is not a partial group list. Nulls still do not contribute to the aggregates, and a null key is still a group. A filter that matches no rows returns `{"groups":[]}`. Keys come from the rows that survive the filters.

`GET /events/latest?from=&to=&by=field` returns a JSON array with one object per distinct value of that column: the matching row with the greatest timestamp. A tie keeps the later row in ingest order. The objects use the same field order and nulls as `GET /events`. Repeat `select=field` to project those fields, including a filter on a column that is not selected. `from`, `to`, `eq`, `gt`, `ge`, `lt`, and `le` filter first. A block the sparse index places outside the range is not read. A block the zone map can reject is not read. The array is ordered by the key: null first, then the same order as grouped `GET /events/stats`. A null key is one object whose key field is JSON `null`. No matching row is `[]`. More than 4096 keys is status `400` and the body is not a partial array. `by` is required. A second `by`, an empty name, an unknown field, a float, or a json column is status `400` and does not read the store. `limit`, `offset`, and `bucket_ms` are status `400`. `by` on `GET /events`, `GET /events/count`, `GET /events/histogram`, `GET /events/distinct`, `GET /events/topk`, and `POST /events/drop` is status `400`. `latest` is not a parameter of those routes, of `GET /events/stats`, or of `GET /events/topk`.

`GET /events/distinct?field=` returns `{"count":N}` for that same range and the same `eq`, `gt`, `ge`, `lt`, and `le` filters. `field` is required. `N` is the number of distinct non-null values that column takes among the rows that survive the filters. Nulls do not count. No non-null match is `{"count":0}`. An int, timestamp, decimal, bool, string, or text value compares with the same equality grouped `GET /events/stats` uses for a key. A float compares by IEEE-754 bits, so `0.0` and `-0.0` are one value when those bits match and two values when they do not. A non-finite float is the same corrupt error a float sum returns. More than 1,000,000 distinct values is status `400`, the body says `distinct value limit exceeded`, and the body is not a partial count. A missing `field`, an empty name, an unknown field, or a json column is status `400` and does not read the store. `by`, `select`, `limit`, `offset`, `bucket_ms`, `sum`, `min`, `max`, `quantile`, and `topk` are status `400` on this route. `distinct` on `GET /events`, `GET /events/count`, `GET /events/histogram`, `GET /events/stats`, `GET /events/latest`, `GET /events/quantile`, `GET /events/topk`, and `POST /events/drop` is status `400`. A block the sparse index places outside the range is not read. A block the zone map can reject is not read. When the request has no row predicate, each block is checked from its timestamp column. If every payload timestamp is inside the inclusive range, a bool zone contributes 0, 1, or 2 and an exact string or text zone contributes its values. Nulls do not count, so an all-null column contributes nothing. Those sets are unioned and the column is not decoded. A bloom, an unknown zone, a float, an int, a timestamp, a decimal, or a json column still walks the rows. One int, timestamp, or decimal, with no row predicate, counts a block from its column body when every payload timestamp is inside the inclusive range and the column has no nulls. A constant, a stride, or stride pieces whose stride is -1, 0, or 1 and whose values do not wrap are inclusive intervals, and the count is the size of their union. Rows are not inserted one by one. A null, a bit-packed or frame-of-reference column, a stride other than -1, 0, or 1, wrapping arithmetic, a float, a block the range cuts, or a predicate still uses the value set. A stride of 2 whose values are 0 and 2 counts as 2. A block the range cuts, or any predicate, still walks. A span that mixes a proved zone with a cut block unions the proved blocks and walks only the rest. The sparse index is not that inside check.

`GET /events/topk?field=&k=` returns `{"values":[{"value":...,"count":N}, ...]}` for that same range and the same `eq`, `gt`, `ge`, `lt`, and `le` filters. `field` and `k` are required. `k` is an integer in `1..=4096`. `count` is how many matching rows have that value. The list has at most `k` entries. It is ordered by `count` descending, and equal counts use the same key order as grouped `GET /events/stats`: null first, then numeric order for int, timestamp, and decimal, `false` then `true` for bool, and byte order for string and text. A float with the same count uses IEEE-754 total order. `value` uses the same JSON form as that column in `GET /events`, and a null value is JSON `null`. Nulls are a value, not skipped. No matching row is `{"values":[]}`. An int, timestamp, decimal, bool, string, or text uses the same equality as a grouped-stats key. A float compares by IEEE-754 bits, so `0.0` and `-0.0` are one value when their bits match and two values when they do not. A non-finite float is the same corrupt error a float sum returns. A json column is status `400`. More than 1,000,000 distinct values is status `400`, the body says `distinct value limit exceeded`, and the body is not a partial list. String and text bytes stop at the same 64 MiB ceiling as distinct, with `query response size limit exceeded` and no list. A missing `field` or `k`, `k` outside `1..=4096`, an empty name, or an unknown field is status `400` and does not read the store. `by`, `select`, `limit`, `offset`, `bucket_ms`, `sum`, `min`, `max`, `quantile`, and `distinct` are status `400` on this route. `topk` is status `400` on `GET /events`, `GET /events/count`, `GET /events/histogram`, `GET /events/stats`, `GET /events/latest`, `GET /events/quantile`, `GET /events/distinct`, and `POST /events/drop`. A block the sparse index places outside the range is not read. A block the zone map can reject is not read.

`GET /events/quantile?from=&to=&field=&p=` returns one JSON value: the exact rank of that numeric column over the same range and the same `eq`, `gt`, `ge`, `lt`, and `le` filters. `field` and `p` are required. `p` is a decimal in `0..=1`. Matching non-null values are sorted, and the result is index `floor(p * n)` when `p < 1`, or index `n - 1` when `p` is 1. `n` counts only non-null matches. No non-null match is JSON `null`. An int, timestamp, or decimal uses the same JSON form as that column in `GET /events`. A float is a JSON number. When the request has no row predicate and the column is an int, timestamp, or decimal, a block whose payload timestamps all sit in the inclusive range and whose column has no nulls answers from a constant, a stride, or stride pieces when every stride is -1, 0, or 1 and the values do not wrap. Those runs are merged and the same index is selected without one sample per row. A null, a bit-packed or frame-of-reference column, any other stride, wrapping arithmetic, a float, a timestamp outside the range, or a predicate still sorts the matching values. The sparse-index min/max are not that check. A missing `field` or `p`, a `p` outside `0..=1`, an empty name, an unknown field, or a bool, string, text, or json column is status `400` and does not read the store. `by`, `select`, `limit`, `offset`, `bucket_ms`, `sum`, `min`, `max`, and `topk` are status `400`. `quantile` on `GET /events`, `GET /events/count`, `GET /events/histogram`, `GET /events/stats`, `GET /events/distinct`, `GET /events/topk`, and `POST /events/drop` is status `400`. A block the sparse index places outside the range is not read. A block the zone map can reject is not read.

`GET /events/histogram?from=&to=&bucket_ms=N` returns `{"buckets":[{"start_ms":S,"count":C}, ...]}` for that same range and the same `eq` and range filters. `N` is a positive `i64`. Each bucket starts at `floor(ts / N) * N` using integer division that rounds toward negative infinity, so the starts are aligned to the unix epoch. The list is every bucket that intersects the inclusive range, in increasing `S`, including a bucket whose count is `0`. A row is counted in the bucket that contains its own timestamp, and the sum of the counts is the matching `GET /events/count`. A request that would emit more than 4096 buckets is status `400` and does not scan the store. A missing `bucket_ms`, zero, a negative, a non-integer, `limit`, or `offset` is the same `400`. A block the sparse index places outside the range is not read. A block the zone map can reject is not read. When the request has no `eq`, and either there is no numeric range or the zone implies every numeric range, and the timestamp column is a constant or a positive stride that does not wrap, with no nulls, and both encoded endpoints sit inside the inclusive range, the buckets are filled from that header and the column is not expanded. A range the zone does not prove still reads the rows. An equality, a null in the zone, a negative stride, wrapping arithmetic, stride pieces, or a bit-packed timestamp still reads the timestamps. A timestamp outside the range is not counted, and the sparse-index min/max are not that check.

```bash
curl -sS 'http://127.0.0.1:43123/events?from=1700000000000&to=1700000000000'
curl -sS --get 'http://127.0.0.1:43123/events' \
  --data-urlencode 'from=1700000000000' \
  --data-urlencode 'to=1700000000000' \
  --data-urlencode 'eq=action=click'
```

`POST /events/drop` deletes blocks whose maximum timestamp is strictly less than a caller-supplied cutoff. The body is `{"before_ms": N}` where `N` is a signed integer in the `i64` range. The response is `{"ok":true}`. `N` is not taken from the newest stored timestamp, so one future event cannot expire the table. A cutoff equal to a block's maximum keeps that block. A row older than `N` stays when a later row in the same block is still inside the window. A segment's `.dat`, `.idx`, `.zon`, and `.dict` files are removed only when every block in that segment is eligible. A missing `before_ms`, a non-integer, a JSON array, or a value that is not an object is status `400` and leaves the store unchanged.

```bash
curl -sS -X POST http://127.0.0.1:43123/events/drop \
  -H 'content-type: application/json' \
  --data '{"before_ms":1700000000000}'
```

`GET /health` returns `{"status":"ok"}`. The server listens on localhost and has no authentication. Point it at a directory used by only one process.

## C API

```bash
cargo build -p eventer --release
gcc -O2 -o demo examples/demo.c -I include -L target/release -leventer
LD_LIBRARY_PATH=target/release ./demo ./data examples/schema.json
```

| Function | Behavior |
| --- | --- |
| `eventer_open` | Open or create a data directory |
| `eventer_append` | Copy one JSON event into the pipeline |
| `eventer_flush` | Write and fsync queued events |
| `eventer_query` | Inclusive time range as a JSON array |
| `eventer_query_filtered` | Time range plus one exact string or text column match |
| `eventer_last_error` | Last error string for this handle |
| `eventer_close` | Flush and free the handle |

Return codes: `0` ok, `-1` bad argument, `-2` I/O, `-3` event or schema, `-4` query buffer too small (`*out_len` is the required size), `-5` closed. `eventer_append` returns after the event is queued. `eventer_query` and `eventer_close` flush first.

## How a write moves

1. Parser threads turn JSON into typed rows.
2. One encoder packs rows into a columnar block (default 2048 rows, or sooner on flush).
3. Compress threads run zstd (default level 3).
4. One writer thread batches blocks, appends them to the current segment, then appends sparse-index entries. It fsyncs on flush, close, and durable appends.

Segments rotate after 64 MiB (`seg-000001.dat` plus `seg-000001.idx`). The sparse index stores each block's min/max timestamp. New block frames do not repeat those two fields. A crash can leave a torn tail; the next open scans complete blocks, truncates the tear, and rebuilds the index if it disagrees. Rebuilding a frame that has no timestamps decodes the payload and rewrites only the index. Older 36-byte `EVBK` and `EVBD` headers that still contain the timestamps still scan and decode.

Inside a block, integers, timestamps, and decimals use a constant, a constant stride, up to eight constant-stride pieces, an exact-width bit packing of the delta from the minimum, or a byte-width frame of reference, whichever is smaller. Kinds already written by older blocks still decode. Bools are bit-packed. Repeated strings use a dictionary when that encoding is smaller. JSON columns use that same string encoding on the preserved field text. Nulls are a bitmap.

Each column can be compressed as its own frame. That container is kept when it is at most a quarter larger than one frame for the whole block, and a count or a filter then decompresses frames only through the predicate column. A query that returns rows still reads every column of a block the zone map could not reject. Older blocks are one frame and still decode.

## Benchmark

`eventer-bench` generates events, times `append` plus one final `flush`, then checks that a full-range query returns every row. Generation happens before the timer. The single flush is the only fsync, so the rate is pipeline throughput for a batched load, not the latency of one durable HTTP post.

```bash
cargo run --release -p eventer-bench -- 100000
```

The same 100,000 events, zstd level 3, and 2048-row blocks are what [CHANGELOG.md](CHANGELOG.md) compares across format versions. On `96e1ceb` that run stores 3,639 data bytes and 674 index bytes (49 blocks, one segment): 2,815× smaller than the 10,244,000 bytes of raw JSON. The first columnar store, on the same events, stored 394,005 data bytes and 1,968 index bytes (26×). Throughput depends on the host and is not part of that table.

## Rust API

`Store::append_json` queues an event. `Store::flush` and `Store::query` make queued events durable and visible. `Store::append_json_durable` waits until that event's block is fsynced. `Store::append_json_batch_durable` parses every event before queueing any of them, then fsyncs the batch once. A one-object HTTP `POST` uses the single-event path. An array `POST` uses the batch path. `Store::query(from_ms, to_ms)` returns matching [`Row`] values in ingest order; use [`RowSerializable`] or [`row_to_json_bytes`] when you need the original JSON lexemes (including duplicate keys). `Store::query_json` returns the same data as one JSON array for HTTP.

`Store::query_with_filter` adds equality predicates and numeric ranges. Several predicates are AND-ed. `Predicate::Eq("type".into(), "assistant".into())` keeps one value. `Predicate::In` keeps any listed value. `Scalar::Null` matches null. `Predicate::Cmp("user_id".into(), CmpOp::Ge, Scalar::Int(5))` keeps ints greater than or equal to 5. `CmpOp::Gt` and `CmpOp::Lt` are exclusive. Ranges apply to int, timestamp, decimal, and float columns. Nulls do not match a range. The zone map skips a block that cannot contain those values, including an integer, decimal, or float block whose min/max miss the range. A float equality still reads a block whose range contains the value. JSON is not a skip. A block that is read, and whose filter column is a constant or dictionary that does not contain the value, is not fully decoded, so later text columns stay unread. The C equivalent is `eventer_query_filtered` for one string or text column. `Store::query_window` and `Store::query_json_window` apply the same filters, then skip `offset` matches and stop after `limit` rows. The HTTP `limit` and `offset` parameters use that path. `Store::query_json_columns` is that JSON array with a column list: selected fields only, in schema order. A sliced block does not decompress a column that is neither selected nor required by a filter. The C query functions are unchanged.

`Store::count` and `Store::count_with_filter` return how many rows the matching unpaged query would. They do not build a JSON array. A block with no predicates counts timestamps only. One string or text equality, with no other predicate, counts a constant or one dictionary-code period from the column header when every payload timestamp is inside the range. A null, a full code vector, raw strings, a second predicate, or a timestamp outside the range still walks rows. One bool equality, with no other predicate, counts a constant or one bitmap period from the column header when every payload timestamp is inside the range. A null, a full per-row bitmap, a second predicate, or a timestamp outside the range still walks rows. When that count also has numeric ranges and the zone implies every one of them, those ranges are dropped before the header count and the range columns stay compressed. A null in the zone is not a proof. A bound the zone does not cover still walks. `Store::histogram_with_filter` buckets those same rows. `Store::histogram` and `Store::histogram_with_filter` split that same count into epoch-aligned buckets of `bucket_ms` milliseconds. More than 4096 buckets is an error and does not read a block. A constant or positive non-wrapping timestamp stride with no nulls, whose encoded endpoints both sit in the range, fills the buckets from the column header. A histogram with no equality uses that fill when the zone implies every numeric range. A range the zone does not prove, an equality, a null in the zone, a negative stride, wrapping arithmetic, stride pieces, or a bit-packed timestamp still walks rows. `Store::aggregate_with_filter` returns `sum`, `min`, and `max` for int, timestamp, decimal, and float columns over that same window. Nulls do not contribute. An exact sum uses a 128-bit accumulator. One float sum with no `min`, no `max`, and no row predicate adds a fully contained block that has no nulls from the encoded float column, in row order, and does not visit the other columns. A cut block, a null, a non-finite value, a `min` or `max`, or a predicate still visits matching rows. A request that is only `min` and `max`, with no `sum` and no row predicate, reads timestamps and takes int, decimal, and float extremes from the zone when every timestamp in the block is inside the range. A cut block, a `sum`, a grouped aggregate, or a predicate still decodes the in-range rows. `Store::aggregate_grouped` splits that result by one bool, string, text, int, timestamp, or decimal column, at most 4096 groups. `GET /events/stats` is those calls. `Store::quantile_with_filter` returns one exact rank of an int, timestamp, decimal, or float column over that same window. Nulls are not part of the sample. One int, timestamp, or decimal with no row predicate selects that rank from a null-free constant, stride, or stride pieces whose stride is -1, 0, or 1 and whose values do not wrap, when every payload timestamp is inside the range. A null, any other encoding, a float, a cut block, or a predicate still sorts the sample. `GET /events/quantile` is that call. `Store::latest_json` returns the newest matching row for each value of one such column, in that same key order, with the same filters and the same column projection as `Store::query_json_columns`. `GET /events/latest` is that call. `Store::distinct_count` counts distinct non-null values of one column over that same window, including a float compared by IEEE-754 bits. More than 1,000,000 distinct values is an error and not a partial count. With no row predicate, a block whose every payload timestamp is inside the range contributes a bool or an exact string or text set from the zone and does not decode that column. A bloom, an unknown zone, a float, an int, a timestamp, a decimal, or a json column still walks. One int, timestamp, or decimal with no row predicate counts a fully contained, null-free constant or unit stride (`-1`, `0`, or `1`) from the column body, as the size of the union of those inclusive intervals. Any other stride, a wrap, a null, a cut block, or a predicate still inserts values into the set. A cut block or a predicate still walks. A mixed span unions the proved blocks and walks the rest. The sparse index is not that inside check. `GET /events/distinct` is that call. `Store::topk` returns at most `k` values of one column ordered by how often they occur, including null. Equal counts use that same key order, and a float uses IEEE-754 bits. `GET /events/topk` is that call. The C API is unchanged.

`Store::rewrite_directory` reads every row of an existing data directory in ingest order and writes them with the current encoder into a destination that is not already a finished store. The source files are not modified. The report gives `stored_data_bytes` and `stored_index_bytes` for both directories, the same totals as `Store::stats`, and `(source − destination) / source` for data bytes and for data plus index. A destination left unfinished by a crash stays unreadable and a later call replaces it. There is no HTTP route and no C API change.

`Store::drop_blocks_before(cutoff_ms)` deletes blocks whose maximum timestamp is strictly less than `cutoff_ms`. The cutoff is an argument, not the newest timestamp stored, so one future event cannot expire the table. A block is kept or dropped as a whole: a row older than the cutoff stays when a later row in the same block is still inside the window. A segment file (`.dat`, `.idx`, `.zon`, and `.dict`) is removed only when every block in it is eligible. A mixed segment is rewritten by copying the surviving compressed frames unchanged and publishing that file with `rename`, so a crash leaves either the old segment or the new one. The segment dictionary stays when any surviving frame was compressed with it. After the call, a query no longer returns a row from a block whose maximum timestamp is below the cutoff, including after the directory is opened again. Rows that shared a kept block stay. `POST /events/drop` is that call with `before_ms` as the cutoff.
